## 2. 为什么选 diepcustom 做底座（源码结论）

1. **复用 diep.io 官方 WebSocket 协议**（`src/Coder/Writer.ts`、`magicNum` 握手），体验 1:1。
2. **AI 与真人同接口**（`src/Entity/AI.ts` 的 `Inputs` 类）：AI 只输出 `mouse + movement + flags`，走同一套炮管转速、冷却、后坐力物理——"可反制"的架构保证。
3. **性能现成**：25 TPS（`mspt=40`）；增量同步；Camera 只发视野内实体；碰撞与 AI 索敌共用空间哈希网格。官方 Benchmark 模式专门压测几十个满级假人，25~30 实体在舒适区内。
4. **AI 已有雏形**：`findTarget()`（节流+网格查询）、`aimAtTarget()`（可选预判），只需加行为层。
5. **清场功能现成**：`src/Entity/Misc/ArenaCloser.ts`（等级 300 的清场者）+ `Native/Arena.ts` 的 `ArenaState.CLOSING` 状态机，直接复用。
6. **升级协议现成**：`Const/Enums.ts` 中已有 `TankUpgrade = 0x4`、`StatUpgrade = 0x3` 消息类型——自建进化树/图鉴面板可直接发标准消息，**不改协议**。
7. **客户端输入是纯 JS 层**（`client/input.js` 绑定鼠标/键盘，渲染核心为 WASM）——移动端适配只需在 JS 层做"触摸→输入"翻译，不动 WASM。

## 4. 改造点

### 4.1 个人乱斗模式（新 Gamemode：`SoloFFA.ts`）

- **bot 互战零成本**：FFA 下每辆坦克自成小队，`AI.findTarget()` 只跳过同队目标 → 25 个 bot 天然互打。
- **BotManager**：维持 `BOT_COUNT = 25`（可配 20~30）。阵亡后 5~10 秒重生（新坦克/难度/流派/位置，离玩家 ≥ 两倍屏幕视野）。bot 出生 15 级起步，之后靠击杀/吃方块自然涨级（与真人同一套 `addScore`/`setLevel` 流程）。
- **地图**：默认 22300²，改为 `updateBounds(30000, 30000)`（或按 `5500×√实体数` 缩放，参照 Spikebox 先例）；方块密度按面积增补。

### 4.2 流派系统：`src/Entity/AI/BotBrain.ts` + `BotBuilds.ts`（新增）

bot 出生抽流派，流派决定进化路线、加点倾向、行为参数三件事。bot 自动进化直接调服务端 API（`setTank()`/`setLevel()`/`statLevels` 直写，Benchmark 模式已有同款用法）。

**进化路线依据真实数据**（`TankDefinitions.json`，56 辆坦克全树，与现行 diep.io 版本一致）：陷阱手从狙击系分出（Lv15 狙击 → Lv30 陷阱手）；粉碎者由基础坦克 Lv30 直接进化；无人机系源头是狙击 → 监督者（Lv30）→ 霸主等（Lv45）。

| 流派 | 权重 | 进化路线（真实树） | 加点倾向 | 行为特征 |
|---|---|---|---|---|
| **强攻** | 25% | 基础 → 双管 → 三重炮 → 三联炮/五重炮/散射炮；副线：机关枪 → 毁灭者 → 湮灭者/混合体 | 伤害、血量 | 直线逼近贴脸输出，不保持距离 |
| **风筝** | 30% | 基础 → 狙击 → 刺客/猎人 → 游侠/潜行者/掠夺者/水管炮 | 伤害、穿透、视场 | 标准卡距离：远了追、近了退、射程内绕圈 |
| **铺场** | 15% | 基础 → 狙击 → 陷阱手 → 三重陷阱/巨型陷阱/自动陷阱/陷阱机枪手 | 装填、穿透 | 布陷阱守株待兔，敌人进圈才接战 |
| **无人机** | 20% | 基础 → 狙击 → 监督者 → 霸主/死灵法师/经理/战列舰/工厂 | 无人机数、伤害 | 无人机前压、本体中距离游走 |
| **撞击** | 10% | 基础 → 粉碎者 → 地雷/尖刺/自动粉碎；副线：侧卫 → 三角艇 → 加速器/战斗机 | 体能、血量、回血 | 高速冲撞，无视射程直接撞 |

**BotBrain 状态机**（所有动作只写 `inputs`）：

```
wander（游荡觅食） ⇄ engage（交战，按流派） ⇄ retreat（撤退回血）
特例：铺场流 = layTraps 状态；无人机流 = engage 内嵌"无人机前压/本体后拉"二级策略
优先级：HP<30% → retreat；视野内有敌 → engage；否则 → wander
```

engage 通用骨架 = 理想射程带 `[minDist, maxDist]` 按流派配置 + 切向绕行。

### 4.3 难度系统：随机但不阴间

| 参数 | 菜鸟 35% | 普通 45% | 高手 20%（上限档） |
|---|---|---|---|
| 决策间隔 | 30 tick（≈1.2s） | 15 tick（≈0.6s） | 7 tick（≈0.28s） |
| 瞄准抖动 | ±10° | ±5° | ±2° |
| 弹道预判 | 关 | 关 | 开，预判量打 6 折 |
| 卡距离执行 | 追着打 | 偶尔后撤 | 标准风筝 |
| 绕行 strafe | 无 | 低频 | 正常 |
| 低血撤退 | 不会 | HP<20% | HP<35% |
| 等级上限 | 30 | 40 | 45（玩家同上限） |

**"无法反制"红线（验收逐条对照）**：
1. 所有动作走 `Inputs`，受炮管转速/冷却/后坐力/惯性约束；
2. 高手档预判量封顶（6 折 + 横向分量上限）；
3. 决策最快 0.28s 一次，低于玩家反应帧率；
4. `viewRange` = 真人屏幕视野（1700），无全图雷达；
5. 无组队无夹击；
6. Overlord/Manager 仅出现在普通/高手档，无人机 AI 继承本体难度档。

### 4.4 回合与清场（保留原版特色）

参照 `Survival.ts` 的回合制先例 + 现成的 `ArenaCloser`：

- **回合制**：每局 10 分钟（可配）。倒计时最后 60 秒全图公告（中文）："清场倒计时 60 秒"；
- **到时触发 `ArenaState.CLOSING`**：Arena Closer 从地图边缘合围（复用现有实体与 `acCount = √width/10` 数量公式），未死的 bot 与玩家都可反抗；
- **结算**：全灭或清场完成后展示本局面板：玩家击杀数/等级/存活时长、击杀你的 bot 及其流派与难度；
- **玩家中途阵亡**：可旁观等待本局结束（原版观战机制现成），也可立即重开新局（bot 全刷新）；
- 玩家死亡重开时同步重置回合倒计时。

### 4.5 移动端 / 平板适配

现状核实：`client/input.js` 只绑定了 `onmousemove/onmousedown/onkeydown`，**无任何 touch 事件**；渲染在 WASM 内完成。适配方案全部在 JS 层：

**① 触摸翻译层**（改 `input.js` 或新增 `touch.js`）：
- 监听 `touchstart/touchmove/touchend`（`passive:false` + `touch-action:none` 防滚动）；
- 多指区分：以触点起始象限分配角色；
- 把触摸坐标换算 `scale` 后喂给现有 `window.input.mouse()` / `keyDown()` / `keyUp()`。

**② 双摇杆布局**（diep.io 官方手游同款交互）：
- **左侧半屏 = 移动摇杆**：按住出摇杆，位移向量 → 模拟 W/A/S/D 的 `keyDown/keyUp`（协议不吃输入改造，纯键值模拟）；
- **右侧半屏 = 瞄准/开火**：拖动即瞄准（→ `input.mouse()`），按住即开火（→ `keyDown(1)` 左键），松手停火；
- 右键/散弹类操作：右侧摇杆向外拉过阈值 = 右键（repel，无人机系坦克需要）。

**③ UI 适配**：
- 新增的 HTML 覆盖层（升级面板/图鉴/菜单，见 §4.6）用响应式布局：手机竖屏两列网格、平板/横屏四列；
- 触屏设备自动放大点击区（≥44px）、自动隐藏键盘提示类文案；
- `viewport` meta、禁止双击缩放、iOS 全屏 `apple-mobile-web-app-capable`；
- 性能档位：检测移动端后自动降渲染分辨率（`devicePixelRatio` 上限 1.5）并减粒子效果，保证中端手机 30~60fps。

### 4.6 进化树 + 图鉴（新增 HTML 覆盖层，全中文）

原版没有这两个功能，是我们新增的。实现为**独立 HTML/CSS/JS 覆盖层**（不碰 WASM 渲染），数据源 = 服务端编译好的 `TankDefinitions.json` + 我们写的中文描述文件：

**① 进化树面板**（游戏中随时点按钮呼出，或 23/24 级升级时自动弹出）：
- 以"你当前坦克"为根，画出 `upgrades` 树的可达分支（下一级高亮，未来分支灰显）；
- 点击可升级的坦克节点 → 发标准 `TankUpgrade(0x4)` 消息（协议现成，服务端已有校验等级逻辑）；
- 每个节点显示中文名 + 一句话定位（如"狙击手：射程远、装填慢"）。

**② 图鉴（坦克百科）**：
- 主菜单和局内都可进入；展示全树：五系（基础/机关枪/狙击/散弹/陷阱/无人机/撞击）分组；
- 每辆坦克一页：**中文名、中文介绍（定位、优劣势、适用流派）、基础数值（血量/伤害/射速/速度）、上级/下级链路**；
- 数值直接从 `TankDefinitions.json` 读取渲染，介绍存 `i18n/tankDescriptions.zh-CN.ts`（新增，纯数据文件）；
- 死亡结算面板加"图鉴回顾"：本局遇到过的 bot 坦克自动点亮（收集要素，可选）。

**③ 升级选择交互改造**：
- 原版 WASM 自绘的升级按钮对中文化和触屏都不友好，故**用自建面板替代**：升到 2/15/30/45 级时弹出中文升级面板（含进化树入口）；
- 加点（7 项属性）同样换成 HTML 面板，发 `StatUpgrade(0x3)` 标准消息；
- 覆盖层不遮挡核心视野：半透明、可折叠、可拖动到屏幕边缘。

### 4.7 全面中文化（分两层）

**第一层：服务端字符串（直接改，零风险）**
- bot 名字池：中文昵称表（如"穿山甲""独角仙""铁憨憨"…按流派分组取名，趣味感）；
- 系统公告/清场倒计时/结算文案/图鉴介绍：全部中文。

**第二层：客户端界面（HTML 覆盖层全中文 + WASM 内文案处理）**
- 所有自建 UI（菜单/升级面板/进化树/图鉴/结算）从第一天就是中文，`lang="zh-CN"`；
- WASM 内嵌的原生 UI（如旧升级按钮、原生菜单）**不修改**，因为已被 §4.6 的自建面板替代/遮盖，玩家实际看不到；
- 游戏画布内的中文渲染（bot 名字随 nameData 同步，客户端渲染任意 UTF-8 名字，原版机制支持，无需改动）；
- 字体：加载中文 webfont（思源黑体子集化，仅取界面用字，控制在 ~500KB；gzip 后更小）。

## 5. 流畅性与资源评估（25~30 实体规模）

### 5.1 CPU（唯一真正的成本）

- 30 实体在官方 Benchmark 设计工况内；峰值实体 ≈ 700（坦克+子弹+方块）；
- 预估：1 核 vCPU 30~50%，2 核 <25%；
- 保险丝：`BOT_COUNT` 与方块密度做成环境变量，tick 超时先降方块密度、再减 bot。

### 5.2 内存

- 预估 200~300MB，2G 服务器无压力。

### 5.3 流量 —— 与 bot 数量无关

bot 是服务端内存实体，不收发网络包。带宽只取决于真人连接数（1 个）：

| 项 | 估算 |
|---|---|
| 首次加载（客户端+中文字体+图鉴数据） | ≈4 MB（gzip 后 ≈1.5 MB），一次性 |
| 游戏中下行（增量同步，仅视野内） | ≈1~3 KB/s |
| 游戏中上行 | ≈0.2 KB/s |
| 每月（每天 4 小时） | **≈1.2 GB** |

### 5.4 部署结论

云服务器完全带得动；本地部署作为备选保留。移动端只是改变了输入来源，不增加任何服务器负担。

## 7. 部署方案

### 7.1 云服务器（默认）

```
浏览器/手机 ──HTTP(S)──> Nginx(80/443)
                ├── 静态文件：client/ + overlay/（gzip）
                └── /ws 反代 WebSocket ──> Node(diepcustom, PORT=8180, pm2 守护)
```

- `npm i && npm run build` → `pm2 start index.js --name diep-solo`；
- 防火墙只开 80/443，Node 仅监听 127.0.0.1；
- 手机平板直接浏览器访问，无需安装任何 App；可选加 PWA manifest 实现"添加到主屏幕"。

### 7.2 本地部署（备选）

- 同一套代码 `PORT=8180 node index.js`，桌面/手机（局域网）均访问 `http://<内网IP>:8180`；
- 零流量、零公网暴露。
